# 퇴고의 제왕

**한 눈에 개정본 보고 원하는 부분만 합치기** 심너울이 만든 원고 비교 도구, 버전 1.3.

HWP·HWPX·DOCX·TXT 원문과 개고본을 나란히 읽고, 바뀐 문단마다 원문 유지 또는 개고 채택을 선택합니다. 선택하면 양쪽 문단이 선택한 본문으로 바뀌고 변경 강조가 사라집니다. 선택 해제와 되돌리기도 가능합니다.

## 사용

1. ‘사용’에서 원문과 개고본을 하나씩 선택합니다. ‘예제로 비교하기’를 누르면 심너울의 「한 쪽이 너무 유리한 게임」 원문과 시연용 개고안을 바로 엽니다.
2. 바뀐 글자만 빨강·초록으로 강조합니다. 문단마다 문구 수정, 문장 교체, 문장 나눔·합침과 전후 문장 수를 표시합니다.
3. 바뀐 **문단 단위**로 원문 유지 또는 개고 채택을 선택합니다. 미선택 문단은 원문으로 저장합니다.
4. 선택한 원고를 새 파일로 저장합니다. 저장 창에서 형식을 선택합니다. **DOCX 두 개를 비교하면 DOCX 또는 TXT**만 선택할 수 있습니다. 기본값은 같은 형식이면 해당 형식, HWPX가 포함되면 HWPX, 그 밖에는 개고본 형식입니다. TXT와 문서를 비교하면 문서 형식을 기본으로 제안합니다.

장면은 **Enter 두 번 — 문단 사이의 빈 줄 하나**로 구분합니다. 빈 문단이 여러 개 연속되어도 장면 경계 하나로 봅니다. Shift + Enter나 문단 여백은 장면 경계가 아닙니다.

Alt + ←/→로 장면, Alt + ↑/↓로 변경 문단을 이동합니다. 원문·개고본과 직접 편집한 내용은 브라우저의 IndexedDB에, 선택 기록은 IndexedDB와 localStorage에 보관합니다. 쿠키는 사용하지 않습니다. 메인의 ‘이어서 비교’를 누르면 파일을 다시 선택하지 않고 마지막 장면부터 엽니다. 본문이 없는 이전 기록은 파일을 한 번 다시 선택해야 합니다.

메인에 브라우저가 추산한 사이트 저장 공간 사용량과 한도를 표시합니다. 각 비교의 ‘기록 지우기’는 확인 후 해당 원고와 선택 기록을 함께 삭제하며, 컴퓨터의 원본 파일은 건드리지 않습니다. 저장 공간 한도는 기기와 브라우저에 따라 달라집니다. 기록은 같은 사이트 주소와 브라우저에만 남고 사이트 데이터 삭제 시 사라지므로, 중요한 원고는 파일로도 저장해 주세요. ‘선택 백업 / 불러오기’는 선택 기록을 옮기는 기능입니다.
로고나 ‘다른 원고 비교’로 메인에 돌아갈 때 현재 선택으로 원고를 내려받지 않았다면 저장 여부를 묻습니다. 저장 후 선택을 바꾸면 다시 확인합니다. 내려받기 요청을 기준으로 판단하므로 브라우저에서 다운로드를 취소했다면 다시 저장하세요.

## 직접 편집하고 다시 합치기

- ‘개고본 직접 편집’에서 현재 개고본 전체를 고칠 수 있습니다.
- ‘합친 원고 편집’에서 현재 선택 결과를 합친 글을 고칠 수 있습니다. 미선택 문단은 원문으로 들어갑니다.
- ‘개고본에 적용하고 다시 비교’를 누르면 원문은 유지하고 수정한 글을 새 개고본으로 사용합니다. 내용이 그대로인 문단의 선택은 유지하며, 새로 고친 부분은 다시 검토합니다.
- Enter는 문단, Enter 두 번은 장면 구분, Shift + Enter는 문단 안 줄바꿈입니다.
- ‘개고본 저장’은 수정한 개고본 전체를, 기존 원고 저장은 선택해서 합친 결과를 내려받습니다. 직접 쓴 글도 브라우저에 자동 보관되며, 중요한 원고는 파일로도 내려받아 보관하세요.

## 지원 범위

- HWP 5와 HWPX 본문, DOCX 본문·표 안 문단, TXT를 지원합니다. DOCX의 머리말·꼬리말·각주·미주·글상자·이미지·자동 목록 번호는 제외됩니다. 변경 내용 추적이 남아 있으면 먼저 확정한 사본을 사용하세요. .doc는 지원하지 않습니다.
- TXT는 UTF-8, BOM이 있는 UTF-16, 한국어 CP949/EUC-KR을 읽고 UTF-8로 저장합니다. 한 줄은 한 문단, 빈 줄은 장면 경계입니다. TXT에서는 문단 안 줄바꿈과 문단 구분을 구별할 수 없습니다.
- HWP 3, 암호·DRM·배포용 보호 문서는 지원하지 않습니다.
- 파일 하나당 30 MB, 본문 100만 자, 4만 문단. 변경이 매우 많은 큰 원고는 부별 비교를 권합니다.
- 본문과 빈 문단을 A4 기본 서식의 새 문서로 저장합니다. DOCX·HWPX는 글꼴·크기·굵게·기울임·좌우 및 첫 줄 들여쓰기·정렬을 보존합니다. HWP·TXT는 서식을 보존하지 않습니다. 쪽 배치·표 모양·그림·테마 글꼴은 재현하지 않습니다.
- 표·글상자·주석은 저장된 순서로 펼쳐 읽습니다. 복잡한 배치나 한글의 변경 추적 검토 중인 원고는 본문만 정리하거나 변경을 확정한 사본을 준비해 주세요.
- 원고 파일 읽기, 비교, 합치기, 파일 생성은 모두 브라우저 내부에서 수행합니다. 원고 처리 서버, API 키, 회원가입, 외부 폰트가 없습니다. 예제 파일은 사이트에서 불러옵니다. 공개 GitHub Pages에서는 Cloudflare Web Analytics로 방문 및 로딩 성능 통계를 수집합니다. 원고 내용·파일명·편집 내용·선택 기록을 통계에 보내지 않습니다. 통계 도구는 쿠키와 브라우저 저장 원고에 접근하지 않습니다. 로컬 및 비공개 미리보기에는 통계 스크립트를 로드하지 않습니다.

## 개발과 GitHub Pages

Node.js 24에서 실행합니다.

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
```

`dist/`가 완성된 정적 사이트입니다. GitHub 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택하세요. `main`에 변경을 올리면 포함된 Pages 작업이 테스트, 빌드, 배포를 실행합니다. 프로젝트 하위 주소에서도 동작하도록 상대 경로를 사용합니다.

`npm run examples`는 예제 TXT에서 HWPX 파일을 다시 생성합니다. 원고 다운로드 링크는 화면에 두지 않으며, 예제 버튼은 준비된 HWPX 두 파일을 직접 읽습니다.

## 패치노트 관리

화면의 패치노트는 `src/patchnotes.json`에서 읽습니다. 앞으로 사용자에게 보이는 기능이나 안내를 변경할 때는 이 파일 맨 앞에 버전, 한국 시간의 ISO 8601 기록 시각, 변경 내용을 추가합니다. 출시 버전은 package.json과 설명서 표시에도 맞춥니다. 과거 기록은 덮어쓰지 않습니다.

문단 편집창에서 선택한 글자 또는 문단 전체의 기본 서식을 직접 바꿀 수 있습니다. 서식만 달라진 문단도 선택해 합칠 수 있으며, 적용한 서식은 IndexedDB 기록에 보관합니다. 화면에서는 설치된 글꼴과 제한된 표시 크기로 미리보기하며, DOCX·HWPX 저장에는 지원 범위의 원래 값을 기록합니다. 기존 기록에는 서식 정보가 없을 수 있습니다.

1.3부터 독립된 부·장 제목을 인식해 제목과 본문으로 구조를 자동 대응합니다. 추가·삭제된 부·장 전체를 선택할 수 있습니다. 제목·본문이 모두 달라지거나 순서가 이동하면 추가·삭제로 표시될 수 있으며, 의미 기반 이동 추적은 지원하지 않습니다. 기존 비교 기록은 선택 ID 호환성을 위해 기존 알고리즘으로 복원합니다.

### 1.3.1 문단 이동
같은 부 안의 고유한 동일 본문 문단을 이전/새 위치로 연결합니다. 두 위치 선택은 함께 적용하며, 부별 본문 문단 수를 표시합니다. 반복 문단과 내용까지 바뀐 이동은 일반 변경으로 표시합니다.
